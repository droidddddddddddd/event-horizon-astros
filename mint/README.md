# Devnet implementation candidate
This is new transaction code, not a live mint. Dependencies could not be installed in the authoring environment; SDK compatibility and transaction behavior must be tested before use. Do not point at mainnet. Use a dedicated funded devnet keypair, never your real wallet seed. Install dependencies, verify package versions against official Metaplex docs, run npm install and npm run build. Prepare 1000 approved permanent metadata URIs in items.json as [{"name":"Astro #1","uri":"https://arweave.net/..."}, ...]. Randomize the allocation order and disclose it before launch. Copy deployment.example.json to deployment.json and fill it. Set SOLANA_KEYPAIR to the local test keypair file path. Run npm run deploy:devnet. If interrupted, inspect deployment-state.json and chain state; do not blindly restart. Copy the resulting state to public/deployment-public.json and add treasury and allowlist from deployment.json. Run npm run dev. Test both phases with eligible and ineligible wallets, wrong prices, wallet limits, sold-out behavior, reserve isolation and transaction failures. No automatic rollover of unsold early items; no cross-phase wallet cap. Reserve mint UI is not provided. The random config-line order is not cryptographically secure; review reveal fairness before mainnet. No mainnet deploy command is included. Reference: https://www.metaplex.com/docs/smart-contracts/core-candy-machine/create and /mint, /insert-items, /guards/allow-list.
